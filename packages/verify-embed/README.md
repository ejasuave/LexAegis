# @lexaegis/verify-embed

A framework-neutral widget that shows the **current registry status** of a Proof of Review receipt on
any web page, and, only when asked, whether a deliberately published package still matches it. It is
one custom element, `proof-of-review-status`, built on the read-only SDK. It needs no wallet, no
LexAegis login, no backend, no model and no indexer, and it signs nothing.

> **Not published.** This package is built and tested in this repository only. The tarball is local
> (`pnpm pack`); there is no npm release and no hosted script URL. Do not paste a CDN link: none exists.

## What it shows, and what it does not

Two separate lines, never combined into one verdict:

| Line               | Words                                                                                                                    | Meaning                                                                                                                                                                                                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Receipt status** | `active`, `revoked`, `superseded`, `not found`, `unknown`                                                                | What the host's trusted registry deployment records for this exact reference, at an observed block. `unknown` is shown for anything that is not a successful, identity-checked read: missing configuration, wrong network, wrong registry code, a failed or slow RPC. Only an authoritative read can say `not found`. |
| **File integrity** | `not checked — no package supplied`, `not checked`, `matching`, `mismatched`, `incomplete`, `unsupported`, `unavailable` | Whether the files of a package, fetched on request, are exactly the files the reference commits to. A download that succeeds is not a match.                                                                                                                                                                          |

An `active` record is the registry's **current observed lifecycle only**. It does not mean the files
are right, the reviewer is trusted or qualified, the content is correct or legally valid, or that a
recipient's acceptance policy is met (signer requirements are not evaluated). The widget never says
"valid", "verified", "trusted" or "approved".

The host page chooses which reference and which configuration the widget displays. Shadow DOM
encapsulates the component's styles and markup; it does **not** protect the widget from the embedding
page's own scripts. A page could show a misleading badge, so a third-party page does not become
trustworthy by embedding it. Anyone can check independently with the SDK, the CLI or the standalone
verifier.

## Install and use

```html
<script type="module" src="./register.js"></script>
<proof-of-review-status
  chain-id="10143"
  registry="0x…"
  reviewer="0x…"
  commitment="0x…"
></proof-of-review-status>
```

`register.js` is **your** module. It imports the built bundle and passes the trusted configuration
(next section). Those two lines are not magic: without the configuration the element shows `unknown`
and explains why. A complete, runnable page is generated by `pnpm embed:example` (see
[examples/embed](../../examples/embed/README.md)).

```js
import { registerProofOfReviewStatus } from './proof-of-review-embed.min.js';

registerProofOfReviewStatus({
  deployments: [{ policy: deploymentRecord, rpcUrl: 'https://your-endpoint.example/' }],
});
```

- **Plain HTML:** copy `dist/proof-of-review-embed.min.js` (or the unminified `proof-of-review-embed.js`)
  next to your page. Everything it needs is bundled; it fetches no script, font, image or stylesheet.
- **Bundlers and TypeScript:** `import { registerProofOfReviewStatus } from '@lexaegis/verify-embed'`
  (typed ESM). Importing registers nothing and makes no request; it is safe in Node and server-side
  rendering (`registerProofOfReviewStatus` then returns `{ ok: false, reason: 'NOT_A_BROWSER' }`).
- **Browser requirements:** custom elements, Shadow DOM, `fetch` with streaming bodies, Web Crypto
  (`crypto.subtle`, which needs a secure context: HTTPS or `localhost`). Current evergreen browsers.

## Attributes

| Attribute                                        | Required | Meaning                                                                                                                                                                                               |
| ------------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chain-id`, `registry`, `reviewer`, `commitment` | yes      | The whole receipt reference. The chain ID is a canonical decimal string (never a JavaScript number); the commitment alone never identifies a receipt. Addresses and the commitment are lowercase hex. |
| `rpc-url`                                        | no       | An endpoint on an origin the host approved (`rpcOrigins` or a deployment's own endpoint). Otherwise the deployment's configured endpoint is used.                                                     |
| `package-url`                                    | no       | A readable review export (`lexaegis.review-export.v1`) the host publishes deliberately, on an approved `packageOrigins` origin. Enables **Check files**.                                              |

Global attributes (`class`, `style`, `hidden`, `aria-*`, …) work as usual. Changing an observed
attribute discards the current presentation and any in-flight read at once, then reads again.

## Trusted configuration

An address in markup, a value inside the bundle or an RPC response can never establish trust. The host
passes explicit records to `registerProofOfReviewStatus(config)`:

| Field               | Meaning                                                                                                                                                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `deployments`       | One to eight `{ policy, rpcUrl }`. `policy` is the SDK `RegistryPolicy` for a deployment you trust (chain, genesis hash, registry address, deployment block, runtime-code hash, execution delay); copy it from the deployment record (see `docs/DEPLOYMENTS.md`). A reference naming any other chain or registry is `unknown`. |
| `rpcOrigins`        | Extra origins an `rpc-url` attribute may use. Optional.                                                                                                                                                                                                                                                                        |
| `packageOrigins`    | Origins a `package-url` may use. Absent: no file check is offered. Optional.                                                                                                                                                                                                                                                   |
| `allowLoopbackHttp` | **Local testing only.** Permits `http://127.0.0.1`, `http://localhost`, `http://[::1]`. Otherwise every endpoint and origin must be HTTPS without credentials, query or fragment.                                                                                                                                              |

Registering again replaces the configuration; connected elements read again under it. A tag already
defined by something else is reported (`TAG_TAKEN_BY_OTHER_DEFINITION`), never replaced. Registering
makes **no** network request.

**Do not put a private provider key in HTML, the bundle or example configuration.** Use a public,
keyless endpoint or your own read-only relay. A key inside an RPC URL is rejected.

## Network behaviour

- **Status read:** one bounded read when the element connects with complete configuration, and again
  on **Refresh** or an input change. At most 15 seconds and 12 RPC attempts (one transient retry per
  read, inside that total), through the SDK's coherent-checkpoint reads: `eth_chainId`,
  `eth_getBlockByNumber`, `eth_getCode`, `eth_call`. Credentials omitted, redirects refused. No
  polling, no service worker, no browser storage, no wallet request, no indexer, model or agent-card call.
- **Check files:** nothing is downloaded until the visitor presses the button. Then one `GET` to the
  configured `package-url` with `credentials: 'omit'`, `redirect: 'error'`,
  `referrerPolicy: 'no-referrer'`, `cache: 'no-store'` and normal CORS. At most 30 seconds. The decoded
  body is counted as it is read and capped at the protocol's encoded export limit (48 MiB), whatever
  `Content-Length` says; this is a **transport limit**, not a definition of valid data. The file is
  parsed by the SDK's strict decoder and compared with the reference built from the host's
  attributes; the file can never supply an endpoint, a deployment or a different expectation. The
  check is local, so a chain failure cannot erase it and a mismatch cannot change the chain status.
  Bytes live only in component memory during the check; cleanup is best effort and the host page is
  not a confidential sandbox. Browsers cannot pin DNS and this widget does not claim to.

### Public-package disclosure

`package-url` is for a **deliberately published, readable** package, preferably synthetic. The URL is
public to the page and its scripts, and the package contains the files in full. Do not place access
tokens, signed storage links or client-evidence URLs there. Confidential evidence should be checked
locally with the standalone verifier or the CLI instead. Encrypted backups and partial exports get
their honest `unsupported` or `incomplete` result; nothing is decrypted or repaired.

## Styling

Inside the shadow root; optional custom properties: `--por-font`, `--por-text`, `--por-muted`,
`--por-background`, `--por-border`, `--por-radius`, `--por-focus`, `--por-active`, `--por-warning`,
`--por-danger`, `--por-neutral`. Every outcome has words and an icon, never colour alone. The widget
uses native buttons with a visible focus ring, a polite live region, `aria-busy` while checking, no
animation (transitions are disabled under `prefers-reduced-motion`), and fits 320 CSS pixels with the
full reference visible. Text is inserted with `textContent` only.
